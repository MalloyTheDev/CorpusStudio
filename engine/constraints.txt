# Single source of truth for the pydantic version used across CI.
#
# JSON Schema serialization details can shift across pydantic releases, so the schema-generation
# job (.github/workflows/web.yml) and the engine test/type-check job
# (.github/workflows/engine-tests.yml) must install the SAME pydantic. Otherwise the engine could be
# tested against a pydantic that emits a slightly different schema than the committed
# docs/contracts + apps/web/src/contracts, making the diff gate flap.
#
# Bump intentionally: change this line, then regenerate docs/contracts and apps/web/src/contracts in
# the same PR (CI diffs them). The engine's own dependency constraint stays the loose `pydantic>=2.0`
# in pyproject.toml; this file only pins the exact CI resolution.
pydantic==2.13.4

# Pin ruff so the lint gate is REPRODUCIBLE. `pyproject.toml` keeps the loose `ruff>=0.5` dep, so without
# an exact pin here CI installs whatever ruff is newest.
#
# This comment used to warn that the config set only line-length, so the gate rode ruff's DEFAULT ruleset -
# which expands across releases - and prescribed either resolving whatever a new ruff flags OR freezing an
# explicit rule set. The rule set is now FROZEN in `[tool.ruff.lint] select`, so this pin no longer carries
# the gate's meaning on its own: a bump can still change ruff's BEHAVIOUR for the selected rules, but it can
# no longer silently change WHICH rules are enforced. That is why 0.15.21 -> 0.16.0 landed with zero code
# changes, where the same bump reported 928 findings against the unpinned set.
#
# Bump intentionally, in its own PR, and re-run the gate.
ruff==0.16.1
